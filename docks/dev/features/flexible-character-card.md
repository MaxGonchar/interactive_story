# Feature: Flexible Character Card

**Status**: Draft  
**Date**: 2026-06-07

## Summary
Replace the fixed-field `CharacterCard` schema with an open `features` map that lets any key/value pair be added to a character without code changes. Only `name` and `memory` are mandatory. The character's prompt text is generated by `CharacterCard.to_prompt_text()` rather than a hardcoded Jinja2 template in `PromptBuilder`.

## Value
- The current schema blocks experimentation — adding a new character attribute (e.g. `goals`, `quirks`) requires touching Pydantic models, the repository, the Jinja template, and tests.
- With an open `features` dict, a new attribute is just a new key in the YAML file. No code change needed.
- Fits the MVP goal of fast iteration while the story format is still being explored.

**Success criteria**: A character YAML with an arbitrary new key (e.g. `goals:`) renders correctly in the system prompt without any code change.

## Scope

### In scope (first iteration)
- New `CharacterCard` domain model with `name`, `memory: list[str]`, and `features: dict[str, str | list[str]]`.
- `CharacterCard.to_prompt_text()` method that renders the character block.
- New `CharacterYaml` storage model matching the new YAML format.
- Updated `CharacterRepository` mapping.
- `PromptBuilder._build_character_profiles` simplified to call `to_prompt_text()`.
- Migration of existing character YAML files in `data/` and `data-test/`.
- Updated tests.

### Out of scope / future
- API endpoint to create or update character cards.
- UI for editing character cards.
- Validation of individual feature value types beyond `str | list[str]`.
- Ordering guarantees for feature keys in the rendered output (dict insertion order is sufficient for now).

## User Flow
This feature has no visible UI change. The author edits YAML files directly:

1. Author opens `data/stories/<story_id>/characters/<character_id>.yaml`.
2. Author adds any key under `features:` — e.g. `goals: ["Find her sister"]`.
3. Author starts/resumes the scene. The new feature appears as a `### Goals` section in the system prompt automatically.

## API Changes
None.

## Data Changes

### Character card YAML — before
```yaml
id: "captain-mora"
name: "Captain Mora"
appearance: "Tall, sea-worn coat"
traits:
  - "pragmatic"
  - "suspicious"
memory:
  - case: "Lost her first crew in a storm"
    reflection: "Never sail unprepared"
```

### Character card YAML — after
```yaml
id: "captain-mora"
name: "Captain Mora"
memory:
  - "Lost her first crew in a storm. Never sail unprepared."
features:
  appearance: "Tall, sea-worn coat"
  traits:
    - "pragmatic"
    - "suspicious"
```

**Constraints (unchanged):**
- `id` must equal the filename `<character_id>.yaml`
- `name` must be a non-empty string

## Backend Changes

### `app/models/storage.py`
- Remove `CharacterMemoryEntryYaml`.
- Replace `CharacterYaml` fields (`appearance`, `traits`, `speech_patterns`, `body_language`, `likes`, `fears`, `memory: list[CharacterMemoryEntryYaml]`) with:
  - `memory: list[str] = []`
  - `features: dict[str, str | list[str]] = {}`

### `app/models/domain.py`
- Remove `MemoryEntry`.
- Replace `CharacterCard` fields (`appearance`, `traits`, `speech_patterns`, `body_language`, `likes`, `fears`, `memory: list[MemoryEntry]`) with:
  - `memory: list[str] = []`
  - `features: dict[str, str | list[str]] = {}`
- Add `to_prompt_text(self) -> str` method:
  - Renders `## {name}` header.
  - Iterates `features`: each key becomes a `### {key}` section; string values render as plain text, list values render as bullet points.
  - Appends `### Memory` section with bullet points if `memory` is non-empty.

### `app/repositories/character_repository.py`
- Simplify `get_character` mapping — remove `MemoryEntry` construction, pass `memory` and `features` directly:
  ```python
  return CharacterCard(
      id=char.id,
      story_id=char.story_id if char.story_id is not None else story_id,
      name=char.name,
      memory=char.memory,
      features=char.features,
  )
  ```

### `app/llm/prompt_builder.py`
- Remove `_CHARACTER_TEMPLATE` Jinja2 template.
- Replace `_build_character_profiles` body:
  ```python
  if not context.characters:
      return "(no characters)"
  return "\n\n".join(char.to_prompt_text() for char in context.characters)
  ```

## Open Questions
- Feature key capitalisation in rendered output: render the YAML key as-is (`speech_patterns`) or title-cased (`Speech Patterns`)? Currently leaning toward title-cased for readability in the prompt.

## Risks
- `dict` insertion order is Python 3.7+ guaranteed, so feature rendering order matches YAML authoring order — no risk there.
- Any existing test fixtures that construct `CharacterCard` or `CharacterYaml` with the old fields will fail until updated — this is intentional and serves as the migration checklist.
